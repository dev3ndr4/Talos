# Talos: Repository-Wide Architectural Mandates

This document takes precedence over all other architectural guidance and serves as the primary source of truth for the Talos project structure and workflows.

## Core Architectural Patterns

### 1. Backend: Domain-Driven Design (Feature-Based)

- The `backend/app/domains/` directory is the heart of the business logic.
- Each domain (Knowledge, Comms, Coding) must be self-contained with its own `router.py`, `schemas.py`, and `services.py`.
- Cross-domain communication should be handled via the `shared/` directory or explicit imports from other domains' services, avoiding circular dependencies.

### 2. Frontend: Feature-Sliced Design (FSD)

- All React components and logic must follow the FSD layer hierarchy:
  - `app`: Global setup (routing, providers, styles).
  - `pages`: Route-level views.
  - `widgets`: Composed UI blocks (e.g., Header, Sidebars, Agent Panels).
  - `features`: User interactions (e.g., forms, buttons that trigger actions).
  - `entities`: Domain models and business logic (e.g., User, Agent, Task).
  - `shared`: Reusable UI primitives (icons, buttons, inputs), API clients, and utils.

### 3. Isolated Execution (The Sandbox)

- All code generated by the Coding Agent **MUST** be executed within the `sandbox` container.
- The `backend` should never execute arbitrary code directly on its host or container.
- Communication between `backend` and `sandbox` must be strictly regulated via a internal bridge network.

## Technology Stack

- **Runtime:** Docker / Docker Compose
- **Backend:** Python 3.12+, FastAPI, Google Gen AI SDK, Motor (MongoDB driver), Pydantic.
- **Frontend:** React, TypeScript, Vite, Custom CSS (Semantic & Centralized), Radix UI (shadcn), Lucide icons.
- **Data:** MongoDB.

## Engineering Standards

- **Validation:** All incoming data must be validated using Zod (frontend) and Pydantic (backend).
- **Security:** Never commit API keys or secrets. Use environment variables.
- **Code Quality:** You MUST run `pre-commit run --all-files` (or target specific files) after making any code changes to ensure all linting, formatting, and safety checks pass before considering a task complete.
- **Design & UX:** All UI development must strictly adhere to the standards defined in [DESIGN.md](./DESIGN.md).
  - Maintain a "Soft/Brand Focused" aesthetic.
  - Use Lucide icons only (`stroke-width={1.5}`).
  - Strictly no emojis in the UI.
  - **CSS:** Use centralized, semantic custom CSS. Avoid utility-first frameworks like Tailwind to minimize bloating and ensure maintainability.
  - Implement "Glass Box" reasoning traces for all AI interactions.
